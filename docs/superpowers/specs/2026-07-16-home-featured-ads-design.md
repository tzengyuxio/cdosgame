# 首頁精選廣告設計

日期：2026-07-16

## 目標

在首頁既有「精選封面」位置加入「精選廣告」，以兩個並排 tab 共用同一個圖片牆。首頁預設仍顯示精選封面；使用者可切換查看隨機精選的遊戲廣告。

## 範圍

- 只使用遊戲條目 `content/games/*.md` 的 `media[]` 廣告，不納入公司、人物或團隊條目的廣告。
- 不新增 content schema 或人工策展欄位；精選廣告由既有 `media[].kind === 'ad'` 自動衍生。
- 不改變精選封面的既有加權抽選規則。
- 不記憶 tab 選擇；每次載入首頁均預設顯示精選封面。

## 資料與抽選

首頁先從已進入該環境發布集合的遊戲中，建立「遊戲及其所有廣告」資料：

```text
遊戲 → media[] 中 kind 為 ad 的項目
```

每次頁面載入時，在瀏覽器端執行兩階段抽選：

1. 從至少有一張廣告的遊戲中，不重複地隨機選出最多 16 款。
2. 對每款入選遊戲，從該遊戲的全部廣告中等機率隨機選出一張。

此設計確保：

- 同一次結果中，每款遊戲最多出現一次。
- 同一遊戲的每張廣告都有機會出現。
- 廣告數量較多的遊戲不會因此提高入選機率。
- 可用遊戲不足 16 款時顯示全部。

SSR 提供穩定的廣告資料與 HTML，但預設 panel 仍是精選封面。JavaScript 載入後才隨機更新廣告圖片牆；同一次頁面生命週期內切換 tab 不會重新抽選，重新整理才會產生新結果。

每張廣告卡顯示被選中廣告的縮圖及遊戲名稱，替代文字為「`<遊戲名稱> 廣告`」，點擊進入該遊戲頁。

## 元件與互動

「精選封面」與「精選廣告」本身就是 tab 標題，兩者並排並共用既有章節標題的底線視覺。啟用的 tab 以文字顏色與較粗的底線標示。

兩個 panel 共用同一個版面位置：

- 桌面：8 欄 × 2 列。
- 680px 以下：4 欄 × 4 列。
- 卡片與既有精選封面使用相同尺寸、邊框、標題截斷及 hover 規則。
- 廣告圖片使用 `object-fit: contain`，完整保留直式或橫式雜誌版面，不裁切內容。

Tab 使用可存取的語意與狀態：

- tab 容器使用 `role="tablist"`。
- 每個按鈕使用 `role="tab"`、`aria-selected`、`aria-controls`。
- panel 使用 `role="tabpanel"` 並以 `hidden` 控制顯示。
- 點擊、Enter／Space 與左右方向鍵皆可切換；方向鍵切換時同步移動焦點。
- 保留清楚的 `:focus-visible` 樣式。

JavaScript 停用時，預設的精選封面保持可見，頁面主要內容不受影響。

## 邊界與失敗行為

- 若發布集合完全沒有遊戲廣告，不渲染 tab 介面，維持目前單一「精選封面」標題與圖片牆。
- 若廣告少於 16 款，只渲染實際可用數量，不補空卡。
- 圖片路徑與必要 media 欄位繼續由既有 content validation 保證；本功能不另建重複的執行期錯誤處理。
- 抽選資料缺少必要值時跳過該筆，避免產生無連結或無圖片的卡片。

## 實作邊界

- 在 `src/lib/` 增加一個純函式，接收依遊戲分組的廣告資料、上限與可注入的亂數函式，回傳每款至多一張的抽選結果。
- `src/pages/index.astro` 負責從 content 建立廣告群組、SSR fallback、tab markup，以及把精簡資料交給瀏覽器。
- `src/styles/global.css` 負責 tab 狀態與共用圖片牆樣式。
- 不新增前端框架狀態管理或第三方套件。

## 測試與驗收

以測試先行方式為抽選函式加入單元測試：

- 結果不超過指定上限。
- 同一遊戲不會重複出現。
- 注入不同亂數值時，同一遊戲的不同廣告皆可被選出。
- 空集合回傳空結果。
- 可用遊戲少於上限時全部入選。

完成後執行：

```sh
npm test
npm run validate
npm run build
```

瀏覽器驗收涵蓋：

- 桌面與手機寬度的 8×2／4×4 排列。
- 預設開啟精選封面。
- 點擊及鍵盤可切換 tab，ARIA 狀態與 panel 顯示同步。
- 切換 tab 不重新抽選；重新整理會產生新結果。
- 廣告完整顯示且卡片連到正確遊戲頁。
